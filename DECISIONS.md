# Implementation decisions

- Data strategy is Option A (the thirteen deterministic generated workloads). No external traces are required.
- The initial implementation covers M1–M4 foundations and the core M6 double-Q agent. Optional SPP-lite, DQN, and ChampSim conversion remain deferred.
- `matmul_blocked`, `spmv_csr`, and `stencil2d` decode their specified loop/event order using vectorized arrays. `bfs_graph` constructs the complete seeded CSR graph and performs a real FIFO traversal; it loops per edge only where conditional discovery stores must be interleaved in exact trace order.
- The E1 runner includes every implemented prefetcher, including `qtable_small`; optional `spp_lite` remains deferred. Future-lookahead is swept over all five specified distances and only the best IPC run is written.
- Agent checkpoint files persist learned weight tables and feature-layout metadata, but not transient PC/page histories or pending decisions. Loading is therefore a warm start of learned policy values with clean per-trace history, which avoids leaking trace-local state.
- Tuning exposes `--records`, `--trials`, `--workload`, and `--no-refine` strictly for pipeline validation. Only the roadmap defaults qualify as the full search. Raw runs are retained in `results/tune`; smoke-search output must be directed elsewhere and is never promoted to `configs/agent_tuned.yaml`.
- The workspace is now a Git repository and commands record its short commit. The full evaluation must still wait until the real tuning campaign finishes and the resulting tuned YAML files are committed in a distinct freeze commit.
- In-flight prefetch occupancy is maintained with an active-ID map and ready-time heap instead of scanning all L2 entries. DRAM window utilization uses binary searches over ordered, non-overlapping service intervals. These are exact bookkeeping changes: the timing reference suite is unchanged, while the profiled 500-record one-workload baseline grid fell from about 17 seconds to under one second unprofiled.
- Tuning checkpoints are append-only JSON Lines files written after each complete candidate. `--resume` ignores a malformed final line from an interrupted append and reruns that candidate; it never resumes halfway through a candidate.
- Checkpoint filenames include the simulator configuration hash, source-code hash, record budget, trial count, and search seed where applicable. A changed implementation cannot silently resume candidates evaluated under older semantics.
- The specified `pf_backlog_cycles = 4 * transfer_cycles` starves prefetch feedback, so the default remains 32 transfers, matching the demand-MSHR window. S1 explicitly reruns factor 4 so this deviation is visible rather than hidden.
- Cache replacement uses one `OrderedDict` per set. This favors clarity and exact LRU behavior; profiling will decide whether array-backed tags are needed.
- Bandwidth utilization is calculated from exact request intervals rather than approximate buckets. It has the same specified window semantics and is deterministic.
- With the specified backlog threshold, a future lookahead of 4 or more cannot bootstrap a saturated sequential stream: its first prefetch does not become useful before later requests are dropped. Therefore local tests treat it as the diagnostic described in section 5.6 and do not assert speedup; the stricter controlled-trace T9 expectation will be revisited with the full quick-evaluation setup and reported if it remains inconsistent.
- Interval `window_coverage_proxy` is recorded as useful prefetches divided by L2 demand accesses in the window. The specification names the field but does not give a formula; this definition is local, bounded, and does not require a separate baseline replay per interval.
- Generated evaluation traces use a configurable geometric instruction-gap mean of 64 rather than the contradictory original mean of 4. Mean 4 made regular workloads DRAM-channel-bound and flattened the tuning objective; it remains available as `generate(..., gap_mean=4)` for bandwidth-saturated sensitivity runs. Timing microbenchmarks use explicit gaps and are unaffected.
- Default lengths are 10.5 million records for `matmul_blocked` and 5.5 million for `stencil2d`, which brings both above the required 400,000 measured L2-demand decisions after the 10% warm-up. The other defaults are unchanged.
- `hash_lookup` models eight 8-byte buckets per cache line. Linear probes therefore usually hit the primary bucket's line, as specified.
- The main agent is purely learned: `admission_control` and `reach_control` default off and are excluded from random search. The explicit `bw_gate` remains the simple-rule comparison. `PC_D2` remains implemented but is disabled in the main pattern set because it is indistinguishable from `PC_D1` on constant strides and prevented the specified behavior check from identifying the intended action.
- Perf-reward, cross-page, confidence-table/f7, and 16-action mini-agent extensions are deferred and are not included in E3/E12 claims. SPP-lite and DQN remain optional/deferred. Building any of these would require a separate equal-budget tuning campaign; they are not silently compared against the main agent.
- Full refinement uses one million records (`--refinement-records 1000000`) rather than the 2M/4M default trace lengths. This fixes the compute budget before training and is recorded in the command line and result metadata.
- Prefetch bookkeeping is garbage-collected after both expiry and pollution windows; demand-line recording is opt-in for future-lookahead only. A one-million-record agent preflight used about 245 MiB RSS and retained roughly two thousand book entries rather than one entry per issued prefetch.
- Expiry is processed after the L2 demand path, following section 3.7's event order where section 3.4 conflicts.
- Gradual phase transitions occupy the last 50,000 records of a phase and blend toward the next phase. This is the implemented interpretation tested by the phase-variant suite.
- T9's requirement that future-lookahead stay within 2% of no-prefetch on `random_uniform` is rejected: the diagnostic consumes the recorded future demand stream and therefore can prefetch random addresses. Controlled sequential and constant-stride accuracy/speed checks remain enforced; random performance is reported without pretending the diagnostic lacks future information.
